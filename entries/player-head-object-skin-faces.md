# Drawing a player's full body from player-head text objects

The text `object` component with `player` contents draws an 8x8 face. Through
the GUI text shader (see [[hud-corner-text-via-boss-bar-shader]]) each one can
be turned into any face of any body part, so a set of them draws a whole body,
here at a fixed angle with shading. Proven in PayPing.

## What holds on 26.3

- Adventure: `Component.object(ObjectContents.playerHead().id(uuid)
  .profileProperties(List.of(PlayerHeadObjectContents.property("textures", value, signature)))
  .hat(true).build())`. Sending the signed `textures` property means the client
  draws the skin without looking the profile up. With only an id (offline-mode
  players have no textures), the client draws the default skin for that UUID.
- The glyph advances 8 and renders through the GUI text pipeline (`text.vsh`
  with `IS_GUI`), so the vertex shader can move it. The style colour tints it,
  and the shader sees that colour, so marker colours work on heads too.
- It is two quads sampling the 64x64 skin with normalised UVs: the face at
  texels (8,8)-(16,16) and, with `hat`, the hat layer at (40,8)-(48,16).
  `texel = UV0 * 64`: `x >= 32` means the hat quad; the corner is
  `s = step(0.5, (x - (hat ? 40 : 8)) / 8)`, `t = step(0.5, (y - 8) / 8)`.
- Rewrite `texCoord0` to `(rect.xy + vec2(s, t) * rect.zw) / 64` to show any
  skin rectangle, and put the corner anywhere (`TL + s*(TR-TL) + t*(BL-TL)`):
  parallelograms give an isometric look. Nearest sampling keeps it pixel-crisp.
- Glyphs draw in text order, so emit faces back to front. PayPing draws 18
  faces (front, side and top of head, body, arms, legs), each with its overlay
  quad. Shade by setting the vertex colour to grey (top 1.0, front 0.92,
  side 0.72). The face table is generated by `plugins/PayPing/tools/body_model.py`.
- To know which face a glyph is, the shader reads the green channel (16 + face).
  The toast origin comes back from the pen position: the server places face i at
  `left + 8 * i`, so `left = local - s * 8 - 8 * i`.

## Slim ("Alex") arms

Slim skins use 3 px arms at the same UV origins, so a wide-arm face table shows
a stray column from the neighbouring face (seen on 26.3: an orange pixel and a
seam on the shoulder). Keep a second set of arm faces (3 px wide, arms at
x -7..-4 and 4..7) in the face table and send those instead for slim skins.
The client's choice of model:

- With a `textures` property: base64 JSON, `textures.SKIN.metadata.model` is
  `"slim"` for slim; absent means wide.
- Without one (offline mode, or no `SKIN` entry): the client uses
  `DefaultPlayerSkin.get(uuid)`, i.e. skin `floorMod(uuid.hashCode(), 18)`;
  indexes 0-8 are slim, 9-17 wide. An offline-mode UUID is
  `UUID.nameUUIDFromBytes("OfflinePlayer:" + name)`.

## Not proven

- The `textures` metadata path in game: the offline-mode test server has no
  signed skins, so only the default-skin path was seen working; reading
  `"model": "slim"` is covered by unit tests (SkinTest) only.
- Legacy 64x32 skins (the client converts them to 64x64, which should work).
